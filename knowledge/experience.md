# 實作經驗

## 2026-11-20 — 靜態每日學習流程的狀態管理

### 可重用經驗

- 每日任務要有日期邊界明確的佇列；將當日佇列、目前索引和學習狀態放進 `localStorage`，避免重新整理時重派新字或跳過尚未完成的字。
- 連續練習天數應在使用者完成整份當日佇列後更新。單題作答只能更新單字熟悉度，不代表整次練習已完成。
- 日期 key 使用本地年月日組合（`YYYY-MM-DD`），日期運算採本地 `Date`，以符合使用者的日曆日複習節奏，避免依賴瀏覽器對特定 locale 格式的實作。
- 靜態網站可以用 GitHub Pages 直接發布，但 `localStorage` 資料只屬於目前瀏覽器／裝置，不會跨裝置同步；在沒有後端時要在使用說明中清楚說明這個範圍。
- Pages 部署 workflow 使用 GitHub 官方 Pages artifact/deploy action，採明確的最小權限，並在 repository 的 Pages 設定中選擇 GitHub Actions 作為來源。

### 適用範圍

適用於無帳號、無跨裝置同步需求的個人靜態學習工具、每日 checklist、簡易習慣追蹤器，以及由 GitHub Pages 發布的純前端原型。若資料需跨裝置同步、多人共用、可靠備份或涉及敏感資訊，應改採有後端和使用者帳號的架構，不應把 `localStorage` 當成唯一資料庫。
