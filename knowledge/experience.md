# 實作經驗

## 2026-11-27 — 每日新內容配額與複習量分離

### 可重用經驗

- 若設定名稱是「每日新字數」，配額只應限制新內容數量；到期複習是另一種任務，不能從新字額度扣除。佇列可先放複習，再額外加入所選數量的新內容。
- 本機儲存資料和使用者匯入檔都應通過同一個狀態正規化流程：只保留允許的日期、索引、列舉設定和合理範圍內的佇列位置。這可降低舊版、損毀或手動修改資料讓頁面狀態失效的機會。
- 驗證數字索引時，除了檢查數值範圍，還要把保留的鍵轉成標準十進位字串；否則像 `"01"` 的鍵會被讀成索引 1，後續卻以 `"1"` 查不到進度。
- 介面說明、README 和實際佇列規則要使用相同的配額語意；內容庫不足時應明確表示實際派發量可能較少。

### 適用範圍

適用於有「新內容」和「待複習內容」兩種來源的每日學習佇列、任務排程和本機 JSON 備份匯入流程。若產品的設定明確代表「每日總任務數」，則應另外命名並以總量配額實作，不套用新內容專用配額規則。

## 字庫來源與程度標籤

- CEFR 詞彙標籤需對照可信詞典中相符的詞義；若條目沒有標示或詞義不對應，就留白，不以使用者整體程度或主觀印象補猜。
- 在字卡旁註明來源等級是詞彙層級資訊，不等於對學習者程度的診斷；保留來源清單可供後續校對。
- 新詞應追加在字庫尾端；進度備份以字庫索引儲存狀態，若重新排序既有字會讓舊備份對應到錯誤單字。
- 主題數量宜兼顧實際語義與整體覆蓋；以 24 字的示範庫為例，三類維持在 7–9 字即可，不為了數量完全相同而誤分類。

### 適用範圍

適用於以陣列索引儲存學習紀錄的靜態詞彙工具，以及需要展示外部詞典程度標記的學習內容。採用其他詞典或詞義時，應重新核對來源，並避免將詞彙標籤當成課程級別或個人程度評量。

### 備份匯入／匯出回歸檢查

- 測試瀏覽器端備份功能時，可用 mock Blob、Object URL、下載連結和 file input，直接驗證輸出 JSON 版本、檔名、內容欄位及匯入後狀態，不必真的下載檔案。
- 匯入佇列若位置已到尾端，啟動當日練習會立刻視為完成並依既有規則更新 streak；測試需區分這是完成狀態行為，而非匯入清理失敗。

### 適用範圍

適用於無外部服務的前端下載／檔案匯入流程，快速回歸驗證資料封裝與錯誤處理。仍需在真實瀏覽器確認實際下載、檔案選擇與使用者操作體驗。

## 瀏覽器語音播放

- 詞彙工具可用瀏覽器內建 `speechSynthesis` 加上使用者點擊播放單字，不必為基本發音播放另接伺服器或下載音檔；播放前取消舊 utterance，避免快速連點時語音重疊。
- 在主動回想題型中，聲音也可能洩漏答案；只在單字已顯示時提供播放控制，並於中翻英揭曉前隱藏。

### 適用範圍

適用於單字、短語等語言內容的輕量發音輔助。語音品質和可用性依瀏覽器及裝置而異；若需一致的母語者錄音、口音選擇或離線保證，應改用經授權的音訊資料並補上來源與授權資訊。

## 2026-11-20 — 靜態每日學習流程的狀態管理

### 可重用經驗

- 每日任務要有日期邊界明確的佇列；將當日佇列、目前索引和學習狀態放進 `localStorage`，避免重新整理時重派新字或跳過尚未完成的字。
- 連續練習天數應在使用者完成整份當日佇列後更新。單題作答只能更新單字熟悉度，不代表整次練習已完成。
- 日期 key 使用本地年月日組合（`YYYY-MM-DD`），日期運算採本地 `Date`，以符合使用者的日曆日複習節奏，避免依賴瀏覽器對特定 locale 格式的實作。
- 靜態網站可以用 GitHub Pages 直接發布，但 `localStorage` 資料只屬於目前瀏覽器／裝置，不會跨裝置同步；在沒有後端時要在使用說明中清楚說明這個範圍。
- Pages 部署 workflow 使用 GitHub 官方 Pages artifact/deploy action，採明確的最小權限，並在 repository 的 Pages 設定中選擇 GitHub Actions 作為來源。
- 同一份單字佇列可以用可切換提示方向提供主動回想：英翻中顯示英文提示，中翻英顯示中文提示；揭曉時再顯示完整卡片。題型選擇應和當日佇列分開保存，避免切換題型重排每日任務。

### 適用範圍

適用於無帳號、無跨裝置同步需求的個人靜態學習工具、每日 checklist、簡易習慣追蹤器，以及由 GitHub Pages 發布的純前端原型。若資料需跨裝置同步、多人共用、可靠備份或涉及敏感資訊，應改採有後端和使用者帳號的架構，不應把 `localStorage` 當成唯一資料庫。切換提示方向適用於單字、概念卡片、問答複習等具有提示與答案的內容。

## 每日設定

- 新字數量設定應是每日佇列生成的輸入，而不是即時改寫已持久化的當日佇列；清楚標示新設定從何時生效，避免使用者更改設定後誤以為今天的任務沒有更新。
- 當可用內容總數有限時，設定較大的日配額也應只派發現有的新內容，不重複已熟悉或已安排複習的項目。

## 新字主題篩選

- 主題篩選應只影響新內容來源，不應把已排定的到期複習藏起來；使用者選擇興趣主題時，仍需完成記憶排程的複習責任。
- 每日佇列一旦生成就保持穩定，配額或主題變更從下一日生效，這能讓重新載入和中途調整偏好不會改變今天的任務。
- 示範資料的主題標籤是內容分類，不代表正式程度分級；分類數量不足時應提示或保留「全部」選項，而不是宣稱完整課程覆蓋。
### 主題與回歸驗證補充

- 以簡單的 DOM／`localStorage` 模擬流程驗證刷新續練、中翻英先隱藏答案、變更新字偏好不改變當日佇列、整份完成後更新 streak、同日刷新不再派字。
- 當使用者無需建立帳號時，這類短流程模擬可快速檢查純前端狀態轉換；發布前仍應在真實瀏覽器檢查版面、日期邊界及 Pages 路徑。

## 本機進度備份

- 在不設帳號、不接後端的前端原型中，可提供明確的 JSON 匯出／匯入，讓使用者自行備份或移轉進度；匯入前需確認會取代目前資料，並驗證格式及限制索引／欄位範圍。
- 手動備份只提供可攜性，不等同雲端同步、即時備份或可靠還原服務；README 應說明檔案由使用者自行保存，資料不會自動上傳。
- 匯入狀態後要重新啟動當日佇列，且保留同日已完成標記，避免匯入後意外再派新字。

### 備份／移轉流程驗證補充

- 模擬下載檔案產生、合法 JSON 還原、錯誤版本拒絕及越界字詞索引過濾；匯入後保留當日進度與偏好。
- 對於 JSON 檔案匯入，應驗證格式版本，僅複製允許欄位，並把資料索引限制在目前內容庫範圍內；不可直接把使用者匯入的物件當作 HTML 或任意應用狀態使用。
